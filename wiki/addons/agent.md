# Agent

`AgentAddon` in [api.dart](../../app/lib/addons/agent/api.dart) is compiled in and always on (the Add-ons page and its per-device switches were removed 2026-10-30), and has no add-on dependencies. Registration opens no vault, agent, transport or timer.

It registers:

- The `chat` note type with chip, card, embed and full-page builders. `bodySource: 'agent'` records that its transcript stays in the agent store, outside vault pages. A full-page presentation selects its session by ID. Its embed/card builders accept a bare session ID (or the primary indexed identity `chat:<session-id>`) and draw a folding card with the chat title and chapters. Range-JSON references retain their original card. Registration does not mirror chats into the vault.
- The existing `chat_ref` block with explicit Markdown, clipboard and plain-text fallback codecs. Its block-backed Chat slash item keeps the same menu position and insertion path. A populated block calls its context's registered chat embed builder with the session ID and opaque message-range target. Cache updates still refresh the target and searchable summary; the existing folded card is unchanged.
- `agent.open` (Ctrl+J), and the existing dev replay command when enabled. The generic `shellPanels` entry supplies the desktop dock wrapper, header toggle and full-screen/mobile builder.
- The desktop and Android Agent settings sections, on the Agent page (MCP servers on Connectors, under Tools for the agent).
- The indexed `agent` search source: Chats group, chat type chip, existing row icon and labels, and source-owned navigation. Core ranking and persisted title/chapter/section summary rows remain unchanged. Grouped Ctrl+K and mobile search treat targets as opaque; this add-on decodes session/message anchors.

Files: `agent_store.dart` owns the local/Hub client, sessions, stream, lifecycle and index reconciliation; screen/panel/chat/composer/turn/transcript/markdown/cell files draw the chat; `scratch_chat_pane.dart` is the chat (`ScratchChatPane`), with `chat_reader_controller.dart` (scroll position, following the end, pending references, message position; it composes the kit's `OutlineController`), `chat_transcript_view.dart` (rows) and `scratch_user_message.dart` (page and chat chips) beside it; the outline is the shared kit's (`agent_kit`: chapter cards, headings, dividers, the where-am-I strip, Contents, folds, jumps and the indexed list), and `agent_outline.dart` maps the store's `ChatOutline` to the kit's `Outline` (dates parsed, message counts without tool results); the chapter and section menus and the open card get "Add to note" as kit `OutlineAction`s; `chat_reference*`, `add_to_note.dart` and `blocks/chat_ref.dart` adapt references; `chat_type.dart` provides type builders; `chat_search_target.dart` reads and writes a search row's target JSON (`ChatSearchTarget`), `chat_search.dart` opens a hit (anchored range through `openChatReference`, title-only as an ordinary session, a toast when the target or chat is missing); `agent_search_source.dart` and `agent_search_vault.dart` maintain indexed rows; `commands.dart`, `navigation.dart`, settings files and `dev_replay.dart` own the remaining agent behavior. Other code imports only `api.dart`.

The host contract is [addon_services.dart](../../app/lib/services/addon_services.dart): settings and AI-task notification, navigation/page stack, sidebar, sync/login settings, mention UI and marked text styling are explicit transitional surfaces. The add-on imports no old feature, editor or shell implementations directly. Shared UI cards/chips stay in `ui/`. Rust tools and their protocol are unchanged; `AddonContext.agentTools` remains an interface.

When disabled, its type, block, slash item, commands, settings, panel and search source are absent. The agent store refuses to open. Existing `chat_ref` data uses the unknown-block placeholder and the containing page still opens. Grouped search hides unregistered indexed rows. With no registered indexed sources it uses page-only search before ranking and the limit, so cached chat rows cannot crowd out pages.

`app/test/addons/agent/` checks isolated registration, actual page-to-type embed dispatch, disabled placeholders and refused agent opening. `app/test/addons/search_sources_test.dart` checks a fake source independently of Agent. Existing agent/mobile/outline/reference and grouped-search assertions and golden files remain unchanged. See [Add-ons](../app/addons.md) for acceptance results and limits.

## Kit chat pane

The Agent section and the editor dock show the shared [agent kit](https://github.com/BubbleBuffer/agent-kit)'s `AgentChatPane` (pinned in `app/pubspec.lock` and `app/pubspec.yaml` at a commit on its main) through `ScratchChatPane` (`scratch_chat_pane.dart`), inside the kit's `BbThemeScope` fed from Scratch's light/dark and form factor. While the backend is not ready yet, and when the chat asks to sign in, `ScratchChatPane` shows its own shell instead (`_Shell`): the same frame with `ScratchChatBody`, the approval bars and Scratch's composer without a pane slot; signing in has no composer. The phone route and the full-page chat type open `AgentScreen`, so they show the pane too; on a phone the pane runs only on a signed-in hub (signed out, the shell shows the sign-in prompt).

The pane keeps the dock (the composer's state, the error line); everything Scratch looks like comes through its slots: the transcript is `ScratchChatBody`, the composer is Scratch's `AgentComposer` (`composerBuilder`), the header is the full screen's title (the dock has none), and `PaneMetrics` gives the dock Scratch's gutter (12 in the dock, 32 on the screen) and bottom padding (12, 20). Approvals are the one part the pane does not draw: the backend is built with `approvals: false`, so its snapshot and events carry none, and `AgentApprovalBars` (store-backed, keys unchanged) draws them above the composer in the same builder.

The data path is unchanged (Dart, flutter_rust_bridge, `NotesAgent`). `kit_backend.dart` implements the kit's `AgentBackend` over `sessions`, `sessionState`, `eventsAfter` and `subscribe`: `listChats`, `loadChat` and `events` work. Commands go through `KitAgentCommands` (`kit_commands.dart`, `StoreKitCommands` over `AgentStore`), never straight to `NotesAgent`, because the Hub sync gate, `store.error`, the busy counter and the replay mode live in the store. With commands, the backend declares `send`, `cancel`, `approve`, `createChat`, `rename`, `editUndo` and `models`; without them it is read-only (empty capabilities, every command fails with `KitUnsupported`). `store.send` reports failure through `store.error`, so the backend reads it after each call and throws `KitFailed`. A refused undo is a `KitConflict` with the store's reason. A follow-up while a run is active is the same `send` (the engine queues it), and `steer` is not declared. A model pick, a rename and an undo have no event, so the backend makes the open chat reload (a `gap`); `loadChat` shows the client-side model pick even before the first run. References map to the message context: `page` and `mention` become context pages (the label is the title sent), `chat` a context chat, and `selection` a context selection, whose page id, title, block ids and text ride JSON-encoded in the ref's id (`encodeKitSelection`). Scratch sends no message or tool-row events, so `events` forwards run start and finish, approvals and streamed paragraphs, and asks the kit to reload the chat (a debounced `gap`) after tool, queue and settle events.

Scratch's look comes through `scratchTranscriptActions` (`kit_hooks.dart`), passed as the pane's `transcriptActions`: `ScratchMarkdownRenderer` for prose, `summaryOf` (the verb line, `verbSummary`, shared with the old chat's work row), `activityFooter` ("Show code" for a finished group, `CodeDisclosure`) and one `itemBuilder` that draws a user message with `ScratchUserMessage` (chips read live titles from `PagesStore`; a selection travels as a `selection` ref in the snapshot) and a page edit with `AgentEditRow` (Scratch's wording, Open at the changed blocks, undo through the store). The working line is not a kit hook: Scratch's own pane host will draw it.

`ScratchChatBody` (`scratch_chat_body.dart`) is the chat's body: the outline list, the compacted history, the plain list, the sign-in, off and empty states, the project picker, the history setting, the where strip and the replay controls, with the reader controller. It reads the store and draws no composer or approvals. the pane's `_Shell` hosts it above its approval bars and composer, and the kit pane's `transcriptBuilder` hosts it as the transcript (the kit pane's transcript still comes from the store's turns, not the kit snapshot's items, so the outline and the reader keep their anchors). The compacted-history goldens run against `ScratchChatPane`.

The kit pane's dock uses Scratch's composer through `composerBuilder`: `AgentComposer` takes the pane's `PaneComposerSlot` (`slot:`). In that mode the draft text is the pane's, sending goes through `slot.submit` (the chips become the submission's refs, the selection JSON-encoded in its id; the pane creates the chat on the first send, so a new chat is a draft with `chatId: null` and opens through `onChatCreated`), stop and a chat's model pick go through the pane and the backend, and the host pick, the model's shown value and every key stay Scratch's. Without a slot (the old chat) it talks to the store as before. `AgentKitScreen` opens the newest chat once on the way in; a later new chat stays a draft.

The pane follows a store-owned feed for its connection, so view-scope subscription replacement keeps it live and requests a reload across the replacement window. Connection-wide transport gaps also trigger a reload even when they have no session ID. Startup reconciles snapshot and buffered paragraph overlap through a reload, and cancellation stops pending startup work from publishing events.

Mapping gaps (Scratch concept dropped or reduced):

- The chat list has no run status (every row is idle), no cursor and a client-side title filter.
- A user message keeps its attached pages and chats as chips; the attached selection text and blocks are dropped.
- Chapters and sections (outline), page actions, schedule and replay records have no kit counterpart and are dropped.
- Only pending approvals are in a snapshot (no resolved history, no diff). Queued inputs, plan, children, jobs, questions, reasoning text and the context meter do not exist in Scratch; usage holds the last run's token counts only.
- Tool rows are grouped per assistant message, with output cut at 4000 characters; the target is guessed from common argument names. Page edits become file-edit items; an undone edit shows only after a reload.
- The workspace is the project name; branch and worktree do not exist.
- Not declared: steer, queue edits, resume, rewind, fork, archive, questions, children, jobs, plan, context, providers and profiles. Their commands report the missing capability and the pane hides or disables those controls.
