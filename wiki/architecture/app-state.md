# The Flutter app (state)

**Status:** Phase 1 (foundation) built, 2026-09-30; Phase 2 sync and settings built the same day; databases built 2026-10-01; [Today](../product/today.md) core and app built 2026-10-06. Spec: The Flutter app (internal wiki). Code in [app/](../../app). It started as the [Flutter prototype](../prototypes/flutter.md).

## Bridge

- The bridge crate is [app/rust](../../app/rust) (flutter_rust_bridge 2.13). Generated Dart is in `app/lib/src/rust/`.
- **Regenerating the bindings:** run `bash scripts/regen-bindings.sh` from the repository, or `flutter_rust_bridge_codegen generate` from `app/` (codegen 2.13.0; Flutter/Dart must be on PATH). The generator invokes Rust compiler expansion. Two bridge structs with the same name in different API files clash in Dart, so codegen warns about duplicates. The [runner device list](../integrations/agent.md#runner-device-list-2026-10-24) exposes its list, assignment and rename API through `api/ai.rs`.
- `NotesVault` is an opaque handle to one open vault. It exposes the whole [core API](core-state.md): pages, trash, favorites, icons and covers, properties, collections, schemas, views and queries, backlinks, attachments, history, the change feed (`poll_changes`, `wait_changes`), markdown import, rescan, the sync hooks and the bench seed.
- `NotesSync` is the `vault_sync` client for one vault (`sync_once`, `sync_now`, `start`/`stop` of the background loop, `status`, attachment fetching).
- `NotesHub` is the desktop hub server (`start`, `stop`, `address`, `pair`, `unpair`, `devices`).
- `NotesAgent` ([api/agent.rs](../../app/rust/src/api/agent.rs), built 2026-10-08) is the desktop BubblePaw agent over the open vault: `open(vault, data_dir, settings)`, `models`, `sessions`, `create_session`, `rename_session`, `delete_session`, `session_state`, `send`, `steer`, `cancel`, `decide_approval`, `events_after`, `subscribe` (a `StreamSink<AgentEvent>`, the app's first Rust-to-Dart stream) and `run_script`. Local opening is Windows/Linux only. The stage 4b `connect(url, device, token)` transport also works on Android, whose Hub-only chat, settings and authenticated sync are enabled on `mobile-agent` ([state and phone steps](mobile-agent.md)). Conversions are in [agent_impl.rs](../../app/rust/src/agent_impl.rs). Details: [Agent, step 3](../integrations/agent.md).
- Core enums that carry data are flattened into plain structs with a kind field, and block kinds are strings (the core's kind names).
- **Conflict bridge and bindings implemented (2026-10-14; native and targeted Flutter checks pass):** conflict DTOs carry record ID, `Block`/`Subtree`/`Page` scope, complete side content in pre-order with depths, frontiers, lifecycle state, placement anchors, status, applied history and `undone_at`. `NotesVault` exposes pending `conflicts`/`list_conflicts` aliases over core `list_conflicts`, the resolution log, ID-based `Keep`/`UseSide`, undo, diff and the synced auto-resolve policy. Diff spans convert core scalar offsets to Dart UTF-16; overlays preserve original side indices and identify Local from the device ID. The core/sync backend is checked, FRB 2.13.0 regeneration is complete, and 21 Rust bridge tests plus 12 MCP tests pass. Native bridge and fake-agent builds are complete; all 12 targeted Flutter tests pass and analysis reports no issues. See [Conflict format v2](conflict-format.md) and [Sync state](sync-state.md#conflicts).
- `new_id` is synchronous; every other call returns a Future and runs off the UI thread.

## Layers

- `core/`: [vault.dart](../../app/lib/core/vault.dart) wraps `NotesVault` and counts calls in flight. [file_dialogs.dart](../../app/lib/core/file_dialogs.dart) wraps the native file and folder dialogs (`file_picker`). [link_previews.dart](../../app/lib/core/link_previews.dart) fetches and caches bookmark previews. [change_feed.dart](../../app/lib/core/change_feed.dart) polls `poll_changes` every second and 30 ms after each local write, and hands each batch to its listeners. [paths.dart](../../app/lib/core/paths.dart) picks the data folder and writes `notes.log`.
- `state/`: `ChangeNotifier` stores, provided by `AppScope` and read with `context.watch<T>()` or `context.read<T>()`.
  - `PagesStore`: every page by recency, loaded in chunks. After the 400 ms debounce, content-only batches refresh a bounded prefix after the core writer acknowledges the edit, then patch loaded rows, cached metadata and the document list with one notification; count and scan progress stay. Reset, tree/create/delete/move/type changes, unknown old positions or an unrecognised recency prefix use a full reload. Newer batches invalidate pending list reads; a final feed poll rejects reads spanning an undelivered edit.
    Explicit reloads share one request and retry at most five rounds; if the fifth is superseded, the request completes with the latest retained state and schedules one full reload through the normal debounce.
    Calendar category edits change the hidden calendar system page and fall back to a full reload; this known limit is accepted because those edits are rare.
  - `TreeStore`: the sidebar tree, loaded with `list_children` per expanded page. It also holds the favorites (reloaded on every change) and their expanded pages, the sidebar width and collapse, and the pages visited this session.
  - `AgendaStore` ([agenda_store.dart](../../app/lib/state/agenda_store.dart)): one per open vault, owned and disposed by `AppState`. It holds the selected day (today initially), its Monday–Sunday week, initially 50 oldest overdue tasks and their full count, up to 50 completed overdue tasks edited since today's local midnight, and five In motion entries. Every change-feed batch schedules a 150 ms `Debounce` reload; an acknowledged core `flush` makes block-derived dates and progress current before querying. A plain timer reloads at local midnight and follows the new day when today was selected; its delay is at least one minute, and both timers are cancelled on dispose. Timed bounds are local-midnight instants; date-only bounds are UTC midnights of the same calendar days. Week-strip counts and overdue marks are cached when the projection reloads; counts include overlapping ranges. The Home summary keeps today's counts even while browsing another week. Task completion is optimistic, retains its projection until indexing finishes, and reverts with an error toast on failure. Reload requests during pending toggles are retained and run after the last write settles, including failure.
  - `UiState` ([ui_state.dart](../../app/lib/state/ui_state.dart)): what the interface remembers on this device, in `<data dir>/ui_state.json` (never synced, debounced writes): sidebar width and collapse, expanded tree and favorite pages, open toggles per page, the capture Task/Note choice (Task initially), All pages expansion (collapsed initially), and the last open page (reopened at start if it still exists). It belongs to one vault: another vault folder starts it empty.
  - `PagesStore.prefs` / `updatePrefs`: a page's display options (small text, full width, lock, cover position), stored in the page through `set_page_prefs` so they sync. Writes show at once and are written in order.
  - `PageStore`: one `PageSession` per open page. A session holds the edit queue and the page-wide undo stack, and watches the feed. A change that did not come from the editor is loaded and handed to it through `PageSession.external`. A page moved to the trash raises `PageSession.deleted`, and the editor closes.
  - `CollectionStore`: one database's schema, views and rows (see [Databases](#databases)), and `SyncStore` (client, hub, devices, conflicts, attachment fetching; see [Sync and settings](#sync-and-settings)).
- `registry/`: block, property, view and command registries. `registerBuiltins()` fills them at start.
- `blocks/`: the built-in block types, one file each (the headings share `heading.dart`, the toggle headings `toggle.dart`): text kinds, toggle and toggle headings, callout, columns, image, file, bookmark, link to page and sub-page, table of contents, inline database, divider and code. A type declares its label, menu entry, markdown prefixes, behaviour flags (list item, multiline, editable, accepts children) and how it draws. Headings (including toggle headings) project checklist progress from editor order when their section has at least two to-dos; the live bar/count are not stored. Complete sections read “All done”; an editor-local revision emits a 900 ms confetti burst only when a direct user tick completes a section. Load, undo and reduced motion do not emit confetti. Default callouts use neutral paper with a 3 px space-colour seam and a paper icon tile; explicitly authored block fills remain available.
- `editor/`: the page editor ([page_screen.dart](../../app/lib/editor/page_screen.dart)). It asks the block registry for everything kind-specific. Unknown kinds render as a read-only "Not supported on this version of Scratch" card ([unsupported_card.dart](../../app/lib/ui/unsupported_card.dart)) showing the kind and any text; it has no hover, and the editor sends no ops for it. [clipboard.dart](../../app/lib/editor/clipboard.dart) converts blocks to and from markdown; the mention and colour menus and the block pickers live beside it.
- `ui/`: the UI kit. The tokens and notes-free primitives come from bb-ui (`bb_tokens`, `bb_ui`) and their files here are re-exports; see [UI and agent-kit dependencies](agent-kit.md). Tokens and `FormFactor`, icons (Lucide glyphs behind `Ico`/`Ix`, [lucide.dart](../../app/lib/ui/lucide.dart)), `AppTooltip` ([tooltip.dart](../../app/lib/ui/tooltip.dart); new UI uses both, see [Design](../product/design.md#icons-and-tooltips-2026-10-21)), `Hover`, buttons, fields (`PlainField`, `SearchField`), menus and popovers, sheets, page icons, routes and formatting helpers. Screens build only from these. Stacks phase 1 (2026-10-07) uses desk/sheet and rail tokens, asymmetric `Radii.ctl/field/panel`, seam/stack shadows, a shared hover/press/focus surface and checkbox. `Motion.of(context)` disables component motion for reduced-animation preferences. Bundled OFL fonts are Atkinson Hyperlegible Next (body/UI), Fragment Mono (times/code), and Bricolage Grotesque (`tsDisplay`, width 90, weight 640, optical size following text size); tests load the same files. Fragment Mono also supplies body-font symbol fallback, including date-range arrows. The committed light tertiary token meets body-text AA. Theme-aware coloured editor text and database chip foregrounds also meet AA on their painted surfaces; token and palette pairs are tested in `stacks_contrast_test.dart`.
- `shell/`: boot, the app shell, home, the desktop sidebar, navigation, search and the built-in commands. Desktop `openPage(stack: true)` retains up to four page routes above Home; internal links push, external actions replace, and an existing page pops back to its route. Non-opaque routes preserve covered editors. `PageStackChrome` paints the pile from `PileGeometry` (2026-10-07): one focusable 58 px spine for the sheet directly below the top, up to three 4 px paper edges for older sheets, everything top-aligned 12 px from the rail and the top; the top sheet always spans the rest of the window. The spine pops one level; a 300 ms hover, a click on the edges or Enter on the spine opens the fan-out list of every sheet plus Home. `PageStackNavigator.firstLines` holds the live first body line of open untitled pages, reported by their editors; `PageMeta.firstLine` (pages_store, from the page `meta()` loads) covers pages that are not open. `pageLabelOf`/`PageLabel` use both, then "Untitled", for the rail, Home's lists and Recent cards, breadcrumbs, search and the @/[[ picker (2026-10-07). `Motion.sheet` transitions, instant with reduced motion. Session restore remembers only the top page. Mobile uses one page-history route with at most 50 entries; only its current editor and the inert neighbour revealed during a swipe are built. Each entry remembers its selected database views for back/forward and previews. History departures save through the same page-store close hook as route pops, and visits and the remembered page follow the active entry.
- `properties/` and `views/`: the property types and the six view layouts, registered in the property and view registries. The database add-on holds the view frame (`DatabaseView`), the `view` block, editors and menus.
- `features/`: the Getting started page, the bench showcase page, the bake-off instrumentation, `page/` (header, cover picker, page menu, breadcrumbs), `backlinks/`, `trash/`, `history/`, `import/`, `database/`, `settings/`, `sync/`, `templates/` and `mounts/`.

## What it does

- The layout is chosen by window width: below 768 px it is the mobile layout, otherwise the desktop one.
- **Shell** (shell track, 2026-10-01):
  - **Sidebar (desktop):** Search, Home, Agent (desktop, when the agent is on; Ctrl+J), then Favorites (only when there are any; they expand like tree rows, with their own expanded state) above Pages (the page tree), and Settings and Trash at the bottom. Tree rows are 30 px and expand lazily. Only pages with children show a chevron (leaves keep its width). The current row has the 3 px bar and a fill lighter than hover. Untitled pages show their first line in tertiary italics, open or not.
    - Hovering a row shows "•••" and "+"; the row keeps its highlight and buttons while its menu is open. The "•••" menu opens beside the sidebar: Add a page inside, Rename (in place), Duplicate (stays where you are), Move to, Add to / Remove from Favorites, Move to trash.
    - Dragging a row moves it with `move_page`. The middle of a target row nests the page at the end of its children; its top or bottom quarter puts the page before or after it. While dragging, a ghost follows the pointer and a line or highlight shows the drop. A page cannot be dropped into its own subtree.
    - The right edge resizes the sidebar between 200 and 480 px (double-click resets to 240). The header's collapse button or Ctrl+\ hides it. `SidebarReopenButton` (in the home and page top bars) shows only while it is collapsed. Width and collapse are saved in `ui_state.json`.
  - **Home, Today:** today's date, event, open due-task and overdue counts, with no greeting. Home sits on the desk, at most 1240 px wide: date/summary and week strip above a 1.6:1 grid, with Today and Recents left and capture, In motion and Favorites right (otherwise stacked). Today has all-day events, timed events and a Now marker, oldest overdue tasks with late-day pills, due tasks and a collapsed done group. Each task group starts with 50 rows and Show N more reveals another 50; limits reset on a selected-day change. The done group on today retains completed overdue tasks so they can be unticked. Due/done database tasks show their configured status label with a group-based pill; overdue rows keep only the late pill. The minute timer uses seconds and milliseconds remaining in the current minute to avoid ambiguous local times during DST fall-back. Task source labels identify their origin: the collection title for rows and page title for to-dos. Tapping opens the page; `PageScreen(initialBlock:)` reveals and briefly highlights a to-do. In motion shows done/total inside a 44 px space-colour progress ring. Recently visited keeps session visits first, then recency, with up to six fan tiles on desktop and a horizontal fan on mobile. All pages is collapsed and excludes database rows as before. Mobile orders date, summary, week, Today, In motion, Favorites, Recents and All pages; capture sits at the top of Today inside the Home scroll view. The single bottom dock keeps its safe-area padding and stays above the keyboard.
  - **Capture** ([daily_capture.dart](../../app/lib/features/daily_capture.dart)): Enter appends a dated to-do or paragraph to the core's one daily note for today; a task uses the same ISO date mark and visible long date as the editor's mention menu. Escape clears the field. Successful capture shows a four-second Open link; Today's note creates or opens the same note. The Journal is discovered by its page role rather than its title.
  - **Mobile navigation (2026-10-10):** Home is the only root screen. Its dock opens the page tree, full-screen search or a new page. A right swipe reveals the tree (including Trash and Settings); a left swipe reveals the full-width existing agent chat. Panels follow the finger with a scrim, and back or a scrim tap closes them. Pages share back/forward history: internal opens append and discard forward entries, while a Home open starts fresh. Right swipes, Android back and the page back button step back, then return Home; left swipes step forward when available. Inner horizontal scrollers and drag handlers win the gesture arena; vertical drags, covered routes, inline editor menus and active text selections do not start navigation. Reduced motion keeps finger tracking and makes release transitions instant. Desktop navigation and full-screen agent opens keep their existing behaviour.
  - **Search:** on desktop, Ctrl+K (unless the editor has a text selection, which adds a link) or Ctrl+P, and the rail's Search row, open a search overlay from anywhere; picking a hit replaces the stack with it. Mobile opens a full-screen search. Each result shows the title (an untitled hit shows its matching text in italics), the page's path (ancestors joined with " / ") and the matching text.
  - **Space colours:** boot calls `ensureSpaceColors` once after opening and seeding. `spaceColor` maps apricot, paw, moss, duvet, sun and sky, with a lighter duvet in dark mode. Stacks phase 3 uses `spacePatch` (fill/deep/ink), separate from the existing dot/pill palette, for filled desktop spines, clipped 6 px sheet bands, page/breadcrumb icon tiles, 22 px rail space tiles, Home folder tabs, checked task boxes and target-space inline underlines. Null or None omits every Tabs treatment and preserves existing apricot ticks. Their page menu offers Colour with six swatches and None; this writes directly without undo. None stores the explicit value `none`, which survives reopening and automatic colour assignment; it omits Tabs and uses the neutral progress colour. In motion and incomplete heading progress retain `spaceColor`. Shared painters draw the prototype calico mark and empty-page sleeping cat. `ConfettiBurst` and `SpaceWiggle` are pointer-transparent decorative feedback where appropriate and respect reduced motion; Today celebrates the last due-today tick in apricot.
  - **Trash** ([trash_panel.dart](../../app/lib/features/trash/trash_panel.dart)): a popover next to the sidebar's Trash row on desktop, a full screen on mobile. Search, Restore and Delete forever (after a confirm). Each row shows its old parent's path while that page exists.
  - **Version history** ([history_panel.dart](../../app/lib/features/history/history_panel.dart)): a 1100×760 modal on desktop (version list on the left), a full screen on mobile (list on top). Versions are grouped by day; selecting one shows it in the real editor, read-only (`PageScreen(snapshot:)`: nothing saved, no outside changes adopted, a detached session); Restore version restores it and closes. Versions from other devices say "Another device".

Import runs `import_markdown` on a folder (at the top level, or inside the current page) with a spinner and a result line; on Android, where a picked folder has no readable path, it picks markdown files, copies them to a temporary folder and imports that (attachments beside them are not brought along).   - **File dialogs** (`FileDialogs`): import, export, attachments (image, file, video, audio, PDF blocks), cover upload and the vault folder (desktop). The attachment pickers keep a "paste a file path" field; a picked file with no path (Android content URI) is added from its bytes. ### Known limits

- On today, the done group includes overdue tasks whose page was edited since local midnight, as an approximation of completion today; another edit to an already completed page can include it too.
- Two app instances opened on the same vault can create duplicate daily notes for the same day.
- Two app instances performing a simultaneous first boot on the same vault can create duplicate starter databases.

## Sync and settings

- **Settings** live in `settings.json` in the data folder (`AppSettings`, provided by `SettingsScope`). They hold the theme (system, light or dark), an optional vault folder, the hub switch and address, the hub URL and token this device connects with, and "download attachments in the background". The token is stored there in plain text.
- **Settings screen:** a modal on desktop (left nav: Preferences, Reminders, Sync, Devices, Conflicts, AI, Vault, About) and a full-screen list on mobile. It opens from the sidebar's Settings row on desktop and from the gear on the mobile home header.
- **Hub (desktop):** on by default and started at boot on `0.0.0.0:47100`. The Sync section lists its Tailscale (100.64/10) and LAN addresses. "Add a device" makes a one-device token and shows the hub URL, the token and a pairing code (`notes://pair?hub=…&token=…`) as text and as a QR code. The QR encoder is pure Dart ([qr.dart](../../app/lib/features/sync/qr.dart)); no package was added. Devices lists paired devices with Unpair.
- **Connect to a hub** (mobile; also on desktop): paste a pairing code, or enter the URL and token. It starts the background `NotesSync` loop and saves the connection, so it resumes at boot. Disconnect stops it and forgets the token.
- **Status indicator:** in the home and page top bars. Synced, syncing, offline (the hub cannot be reached) or error (for example an unknown token). Hovering shows a tooltip; clicking or tapping opens the details with the last message and "Sync now". It is hidden when there is neither a hub nor a connection.
- **Conflict review v2 (2026-10-14, branch feat/merge-screen):** the page is the review. It lives in [features/sync/conflicts.dart](../../app/lib/features/sync/conflicts.dart), with all copy in `conflict_copy.dart` and the Undo toast in `conflict_toast.dart`; the editor only exposes a generic `BlockDecor` hook (tone, a widget above and below a block) in `block_row.dart`, which `PageScreen.blockDecor` fills with `ConflictBlocks`. Section and page conflicts show a topline above the content (`ConflictToplines`) with OK / Use the other version; a trashed or purged page reads "... so it's back in Pages." with OK / Delete again, and OK shows no toast. Purge tombstones carry the purging device when `X-Purge-Device` is negotiated, so the purged side reads Local on that device; older tombstones without an id retain the unknown-device fallback. A block changed on both devices shows one side's text: `conflictShownSide` picks the side with the later `timeMs`, ties to the greater device id in byte order (device ids are ASCII; this matches the core's record-time rule). That line is labelled Local or "Cloud · from <device>", and the other side's text sits under it; one tap takes it. Every action is `Keep` or `UseSide`; the toast after a section or block `UseSide` has Undo (`undoConflict`).
- **Conflict entry points and log (2026-10-14):** phone Home shows "Changed on two devices" with a count pill and card rows at the top (`ConflictHomeSection`); the desktop rail shows a collapsible group with the count above Settings and Trash (`ConflictRailGroup`). Both are mount lines in `shell/home.dart` and `shell/sidebar.dart`, reuse `ConflictRows`, open the page, and are hidden with nothing pending. ## Reminders

- **Store** ([reminder_store.dart](../../app/lib/state/reminder_store.dart)): one per open vault, owned by `AppState`, started after the vault opens. It flushes the index and loads `agenda` and `overdueCount`, including whole calendar days for morning counts and the event lead at the seven-day edge. Change-feed batches replan through a two-second `Debounce`; reminder settings and a clamped local-midnight timer also replan. Backend mutations are serialized, unchanged plans skip `apply`, and disabling cancels notifications without querying the agenda. Closing disposes subscriptions and timers, preserving Android's system schedules.
- **Planning** ([reminder_plan.dart](../../app/lib/features/reminders/reminder_plan.dart)): pure event leads, timed unfinished tasks and local morning summaries over `(now, now + 7 days]`. All-day items appear only in summaries. Summary counts follow Today's calendar-range and end-based overdue semantics. Stable positive 31-bit ids include kind, page, block and instant; page/block payloads open through existing navigation, while `today` returns Home. Source names are loaded by the store because the bridge carries only their ids.
- **Backends** ([backends.dart](../../app/lib/features/reminders/backends.dart)): `flutter_local_notifications` 22.3.1 and `timezone` 0.11.1. Android schedules in `tz.UTC` with `inexactAllowWhileIdle`, reconciles saved pending ids, registers reboot receivers, and asks permission once when a non-empty plan is needed. Desktop (Windows, Linux, macOS) uses a minute ticker while running; reminders over 30 minutes late are consumed without showing. Plugin initialization failure uses the existing in-app toast. Android launch taps are buffered until Home can navigate.
- **Settings:** device-local `reminders.enabled` (true), `leadMinutes` (10), `morning` (480 minutes after midnight) and `permissionAsked` (false) live in `settings.json`. Settings > Reminders offers the switch, event lead and half-hour morning options from 05:00 to 12:00, with disabled selects when off and Android permission-denied text.
- **Testing:** both harnesses inject the fake backend. Planner, coordinator, real-core feed changes, task completion, permission persistence, desktop clock steps, fallback and taps have headless tests; Settings has five new goldens, visually reviewed. Real notification delivery, reboot recovery and Windows toast activation have not been demonstrated on a running device or packaged app.

## Databases

- **Store.** `CollectionStore` holds one collection: schema, views (saved views, or the blocks of a view-block group through a `ViewSource`), the active view and a `RowSource` per query. A `RowSource` loads rows in windows of 100 with `query(offset, limit)` as rows come into view, keeps at most 8 windows (those farthest from the latest load are dropped) and reloads the windows it has when the feed reports a change. Boards keep one `RowSource` per group; calendars and timelines query only the visible date range. Edits are optimistic and then written to the core. The store resolves the top-level space colour once per metadata load (including explicit `none`) and refreshes it on ancestor/tree changes; calendar/timeline pills use it without per-row queries.
- **Property types** ([app/lib/addons/database/properties](../../app/lib/addons/database/properties)): title, text, number, select, multi-select, status, date, checkbox, URL, email, phone, relation, created time, edited time, files, formula and rollup (every kind the core has but person, which is skipped). Files are attachments in the blob store, added through the file-block picker. Formula and rollup cells are read-only values the core computes (an error message shows in the cell); the expression, or the relation, property and calculation, are set from the property menu. Each type declares how it displays, how it is edited, its sort and its filter operators and value editor. Editors open as a popover over the cell on desktop and as a sheet on mobile. Select-like types share an option editor (rename, color, delete, reorder, create by typing).
- **Schema editing.** The column header (or a property row's label) opens the property menu: rename, change type through the type picker, edit options, sort, filter, group, hide, wrap, freeze, duplicate and delete. "+" at the end of the header adds a property.
- **Views** ([database layouts](../../app/lib/addons/database/views), [Board](../addons/board.md)): table, board, list, gallery, calendar and timeline. View blocks on a page are the views: their tabs switch, add, rename, change layout, duplicate and delete them; on mobile a view switcher opens a sheet. Old inline database blocks keep their saved views. View settings cover the name, layout (with card size and preview where it applies), property visibility, filter, sort, group, open-in (mobile only; desktop always opens rows as sheets), duplicate and delete. The rules bar shows filter and sort chips; a rule just added (or the advanced filter) opens its editor under its chip; "Add to advanced filter" switches to and/or groups, marked by an `advanced` flag in the view config. A search box filters by title.
- **Show in Today:** a view-settings sub-page writes the collection-wide agenda role (Auto, Tasks, Events, Off) and date-property override through `setAgendaSettings`. Auto displays its resolved role: a date plus status/checkbox is Tasks, a date alone is Events, otherwise Off. The date list excludes created and edited time and defaults to First date property. These settings belong to the source page, regardless of which view opened the menu.
- **Stacks styling (2026-10-07).** Paper board cards use seam/lift shadows and status-chip headers. Tables use inset headers and a 2 px focus outline. Calendar today uses inverse ink, and calendar/timeline entries use a 25% space tint or info fallback. Row properties retain their editors with a 140 px icon/label column.
- **Interactions.** Table cells edit in place; columns resize and freeze; rows add at the bottom or from "New". Board cards drag between groups and set the group property; "No Status" sorts last. Calendar entries drag to another day (ranges keep their length) and days have "+". Timeline bars move and resize from either end, with week, month and quarter zoom.
- **Rows.** A row opens as a sheet on top of its database on desktop (2026-10-07; the side and center peek are gone), with the database leading its breadcrumb; on mobile it opens as a full page. Row pages show their properties above the editor (`PageProperties`, with "hide when empty" and "N more properties"). Templates: "New" uses the default template (its properties and blocks are copied); the menu next to it lists every template, creates, edits and sets the default, and makes an empty row.
- **Inline and full-page databases.** The `database` block ([blocks/database.dart](../../app/lib/addons/database/blocks/database.dart)) shows a collection inside a page; picking "Database" in the / menu creates a collection under the page and points the block at it. A new blank page offers "Get started with: Database", which turns the page itself into a collection; such a page renders the database under its title.
- **Templates for any page** ([templates.dart](../../app/lib/features/templates/templates.dart), 2026-10-01). An empty page shows one empty state: starter chips under the title (Blank, Database, one per template of its parent, + Template when it has a parent) and the sleeping cat below; all of it goes once the page has content. Picking one copies it into the page. A template page shows a banner ("(Default) template for new pages in …") with "Set as default" and "Turn into page". `PageProperties` wraps the editor with this row; the database's "New ▾" menu uses the same `showTemplateMenu`.
- **Hooks outside these folders:** `addons/database/api.dart` registers the type, property implementations, five layouts and inline block; `addons/board/api.dart` registers Board. `editor/page_screen.dart` keeps the page-properties insertion point and selects its full-page body through the note-type registry. See [Add-ons](addons.md).

## Page links

`notes://page/<page id>` opens that page, and `notes://page/<page id>?block=<block id>` opens it scrolled to the block. [PageLink](../../app/lib/core/page_link.dart) is the one parser and builder (pure Dart); the page menu's Copy link writes the same text. The plan is the internal wiki page "Page deeplinks".

- **Windows registration:** [runner/main.cpp](../../app/windows/runner/main.cpp) writes `HKCU\Software\Classes\notes` (`URL Protocol`, `DefaultIcon` and `shell\open\command` pointing at the running exe) on every start. It rewrites the same values each time, so a moved build takes the scheme the next time it starts. No admin rights. The [installer](windows-install.md) does not write the key; its uninstaller removes it.
- **Single instance:** before the window opens, `SendAppLinkToInstance()` (app_links 7.2.2) looks for a running instance of the same exe. If it finds one, it forwards the link with `WM_COPYDATA`, brings that window forward and the new process exits. A plain launch while an instance is open also just brings it forward. Otherwise the process starts normally, and the link in its arguments is returned by `getInitialLink`.
- **Android:** a `notes://page` VIEW intent filter sits beside the `notes://auth` one in [AndroidManifest.xml](../../app/android/app/src/main/AndroidManifest.xml). Both arrive through app_links.
- **Handler:** [PageLinkListener](../../app/lib/shell/page_links.dart) is started by Home. It takes the link that started the app (it replaces the restored last page) and later links from the stream. Other links, such as `notes://auth`, are ignored. [openPageLink](../../app/lib/shell/navigation.dart) loads the page, shows "No page matches that link." for a missing or trashed page, and otherwise opens it at the block like an external open.
- **Agent chat:** `notes://page` links in agent replies open in-app at the block ([openAgentPageLink](../../app/lib/addons/agent/navigation.dart)).
- **Editor:** a page mark uses the parser for its page id. Its tap opens the page without the block.
- **Tests:** [test/page_link_test.dart](../../app/test/page_link_test.dart) covers the parser (accepted forms and rejected ones). It passes on the Linux machine, as do analysis of the touched files.
- **Not yet run:** the Windows registration and single-instance code were written against the app_links source and have not been compiled or run on Windows. The stream wiring, `openPageLink`, the agent path and the Android filter have not been run on a device or in the widget suites.

## Testing

The headless drive CLI runs the real app and Rust core inside a long-lived, `drive`-tagged Flutter test, with screenshots and visible semantics for shell-driven UX walkthroughs. From the repository root, start it with `python app/tool/drive.py start --desktop --vault fresh`, inspect with `python app/tool/drive.py look`, interact through visible labels or the reading's `eN` references, and finish with `python app/tool/drive.py stop`. It opens no desktop window; forgotten sessions expire after 20 minutes idle. The normal test tiers exclude the session host. `type` sends one character at a time through the platform text-input path, settling briefly between characters, so the `@`, `[[` and `/` pickers open as they would for a person; `type --paste` inserts each line in one edit. Git Bash (MSYS) rewrites arguments that start with `/` into Windows paths, so use `type --slash head` (alias `--key-slash`; `key --slash` presses `/`) or prefix the command with `MSYS_NO_PATHCONV=1`. `start` uses `NOTES_BRIDGE_LIB` when it is set, so a worktree can use the main checkout's built bridge. `state` finds each element's route by walking ancestors, never with `ModalRoute.of`, which would register dependencies and break the next route change (fixed 2026-10-07).

Run from `app/` with `tool/test.ps1 fast|golden|perf|all` on Windows or `bash tool/test.sh fast|golden|perf|all` on Unix. The scripts rebuild the host bridge and fake agent in the shared `target/release` when Rust sources are newer.

- **Fast:** `flutter test -x 'golden || perf || drive'`; functional, widget and integration tests against the real core. Use one exclusion expression: Flutter 3.47 retains only the last repeated `-x` option.
- **Golden:** `flutter test -t golden`; screenshot comparisons in `app/screenshots`.
- **Perf:** `flutter test -t perf --concurrency=1`; the 10,000-row table and board scrolling budgets.
- **All:** fast and golden at Flutter's default file concurrency, then perf separately at concurrency 1. Every file uses independent temporary roots, in-memory settings or vault-local files, ephemeral ports and unique golden output names. The two read-only perf tests reuse a closed seed fixture within their file, with fresh handles and stores.

Both harnesses set the clocks before opening any vault to **Tuesday 2026-10-06 11:20 local time**. The core starts once per test file and advances one millisecond per clock read (resetting between tests would disrupt imported edit ordering), preserving stamp order and unique IDs; the app advances from the fixed instant with a real stopwatch. Production uses the wall clock. The caret is steady in screenshots, and variable paths and ports are scrubbed.

Tests enable `Debounce.instant`: zero-delay timers remain counted in `Debounce.pending`. Other app delays also become instant in tests. `settle` yields to bridge work, pumps animations and explicitly polls the feed until calls and reloads are quiet, with three quiet frames (continuous animations retain a 30-second fake-time cap); pending native work must finish even beyond that frame cap, bounded by a 30-second real-time deadline. `settleUntil` also settles after its condition holds. Index-dependent checks use the core's acknowledged `flush`, not sleeps for its background writer. Real network, image decoding and mount polling still perform real work. `finishAsync` drains real events and fake-zone microtasks without rendering while decoding images or disposing stores; awaiting an existing fake-zone future inside `runAsync` can deadlock.

**Workers:** run the fast tier and the golden files for screens you touched while working; run all tiers once before handing back. For a focused screenshot run: `flutter test test/db_golden_test.dart`. Update only intended goldens with `--update-goldens` and inspect each changed image.

Today coverage uses the real core for week boundaries, limited overdue/count, optimistic completion and rollback, feed-driven progress/settings changes, capture and daily-note reuse, day/week navigation, midnight, page/block navigation, colours, Show in Today and to-do date editing. Demo and first-run seeds have smoke tests. Tagged Today goldens cover home, another selected day, empty home, Colour, Show in Today and to-do chips at 1440×900 and 375×812 in both themes; chip geometry tests also check line height, wrapping and UTF-16 caret positions.

## CI

**Former private repo (until 2026-10-22; now see [Repository and releases](repository-and-releases.md)).** The rest of this paragraph is that repo's setup. `.github/workflows/ci.yml` ran on every push to any branch there. Every job ran on the self-hosted CI runner (`[self-hosted, <ci-runner>]`, runners started by the runner dispatcher); GitHub-hosted runners are not used. The runner's persistent `_work` keeps the Cargo target and Pub cache warm, sccache wraps rustc, the Flutter SDK comes from the runner's tool cache, and flutter_rust_bridge_codegen 2.13.0 and `cargo-expand` are installed in the builder account. The dispatcher allows two notes-app runners at once (`repo_max` in its config, since 2026-10-13), each with its own work dir and Cargo target but a shared sccache and Pub cache; further jobs queue. The global cap of 3 keeps a slot for the other repositories. There is no `pull_request` trigger: a PR from this repository's branch is tested by that branch's push run, and fork PRs never reach the self-hosted CI runner. `android-apk.yml` only starts from a successful CI push run on this repository's own `master` (or a manual dispatch). The fast tier runs half of the self-hosted CI runner's cores. Both jobs check out BubblePaw-base at `release` next to the repo, since `crates/agent` depends on it. `hub-image.yml` also ran on the self-hosted CI runner (see the decision below).

**Decision (2026-10-13):** all CI moves to the self-hosted CI runner; GitHub billing for hosted runners failed and the user chose not to pay or make the repo public. The hosted-only steps and `ci-cache-warm.yml` were removed. `hub-image.yml` moved to the self-hosted CI runner the same day at the user's request: it builds with the self-hosted CI runner's default Docker builder (no volumes, cache trimmed nightly), keeps Docker credentials, the VPS deploy key and known_hosts in 0600 files under `$RUNNER_TEMP` (never `~/.ssh` or `~/.docker`), removes them in an `always()` step, runs only in this repository, and deploys only from `release`; a `dry_run` dispatch builds without pushing and checks the SSH setup with `ssh -G`. Supersedes the 2026-10 split (master on the self-hosted CI runner, other refs hosted).

- **rust:** `cargo test --workspace --locked --exclude notes-tauri`. The Tauri prototype is excluded because the self-hosted CI runner has no GTK or WebKitGTK development packages.
- **flutter:** builds `notes_bridge` in release and BubblePaw's fake extension, then runs `flutter analyze` and the fast tier, `-x 'golden || perf || drive'`. Golden-named files and files that compare golden images are left out too. Goldens are rendered on Windows and do not run in CI.

## Known gaps

- The Android x86_64 release build opens its vault, edits pages and shows the new blocks on the notes-flutter emulator (checked 2026-10-01; [android-home.png](../../app/screenshots/android-home.png), [android-rich-page.png](../../app/screenshots/android-rich-page.png)). - Shell gaps: there are no Teamspaces, Shared or Inbox.
- Home's "All pages" filters database rows in Dart (it loads each unseen parent once to learn whether it is a database). A core filter on `list_pages` would be cheaper.
- Today limitations: Lisbon's standalone page cannot have editable Dates/Status/Budget/Tags without a parent schema, which would turn Trips into a database; that demo subsection is left out. Today was verified headlessly, with no packaged desktop or mobile run.
- The native dialogs were tested only through `FakeFileDialogs`. Windows and Android release builds with `file_picker` compile (2026-10-07); dialog behaviour in packaged apps remains unverified. Linux has not been built.
- Databases: there is no person property. Board columns scroll separately; the timeline lists only rows in its range. A database's own crumb (on its page) still shows the page glyph. An "Empty page" row briefly holds the template's copy (two steps, both synced); a core option to skip the template would avoid that.
- Mobile cannot scan the QR code yet (no camera); it pastes the pairing code. The QR code has not been scanned by a real phone.
- The hub token is stored in plain text in `settings.json`.
- `flutter build linux` has not been run: WSL Ubuntu lacks clang, cmake, ninja, libgtk-3-dev and a Flutter SDK, which need sudo to install.
- There are no font options; "Add comment" does nothing. Dragging a block to the left edge of a plain block does not make columns (only the right edge, or either edge of a column list), so a plain drop just inside the text still moves.
- Unknown block kinds are not a gap: the core keeps their kind, text and target, and they never load as paragraphs. The app shows the unsupported card for them.
